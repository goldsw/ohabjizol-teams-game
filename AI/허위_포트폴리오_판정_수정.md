# 허위 포트폴리오 판정 수정

## 적용 규칙

- 세션 생성 시 지원자마다 허위 존재 여부를 한 번 추첨함. 기본 확률 50%임.
- 실제 품질이 Good/Normal이면 추첨 성공 시에만 더 낮은 허위 품질을 저장함. Bad에는 더 낮은 품질이 없어 허위 품질을 생성하지 않음.
- 저장된 `FakePortfolioQuality`의 존재 여부를 `HasFalsePortfolio`로 조회함. 별도 가변 플래그를 중복 저장하지 않음.
- 포트폴리오 질문은 저장된 허위 품질이 있으면 그 품질로, 없으면 실제 품질로 답함. 문구 선택만 무작위이며 지원자별 답변 캐시 유지함.
- 문서 줄 검증·결과 빨간 표시·허위 인원 수·등급의 허위 인원 입력이 동일한 저장 상태를 참조함.
- 기존 `Applicant.Kind`, 실제 능력치, 표시 능력치는 유지함.

## 확률 설정 경로

- `InterviewScreen` 인스펙터의 **허위 포트폴리오 확률** → `IInterviewSessionHost.CreateStage` → `StageManager` → `InterviewSession`.
- 기존 직렬화 필드 이름 `fakePortfolioAnswerChance`를 유지하여 프리팹·씬 설정을 보존함.
- Campaign/Tutorial 호스트 모두 세션 생성 전에 확률을 전달함.
- `QuestionController`의 기존 float 생성자 인자는 호출 호환을 위해 유지함. 허위 상태는 세션에서 이미 정해지므로 답변 품질을 다시 추첨하지 않음.
- 새 코드는 `QuestionController(Random)` 생성자를 사용함.

## 주요 변경 파일

- `Data/PortfolioQualityRule.cs`: 존재 여부 확률과 낮은 허위 품질 생성
- `Data/Applicant.cs`: 읽기 전용 판정 기준 `HasFalsePortfolio`
- `Rules/InterviewSession.cs`: 확률 검증과 세션 생성 시 한 번 배정
- `Runtime/QuestionController.cs`: 저장된 품질로 답변
- `Rules/VerificationRule.cs`: 저장 상태와 의심 문서 줄의 정합성으로 검증
- `Rules/SelectedTeamSnapshot.cs`, `SelectedTeamResultProjection.cs`, `InterviewScoreProcessor.cs`: 결과 표시와 집계 기준 통일
- `UI/InterviewScreen.cs`, `Runtime/InterviewRuntime.cs`, `Runtime/StageManager.cs`, Tutorial 호스트: 확률 설정 전달

위 경로의 기준은 `Assets/Scripts/Interview/`이며, 호스트 파일은 `Assets/Scripts/Tutorial/`임.

## 회귀 검사

- `Assets/Tests/Editor/PortfolioVerificationRuleTests.cs`: 확률 0/1·기본 50% 분기·유효성·고정 시드 재현·원본 불변·질문/검증/결과 일치·세션 매니저 확률 전달 검사.
- `Assets/Tests/Editor/StageAccuracyRuleTests.cs`: 기존 실제 구현의 소수점 버림 정책에 맞게 3개 테스트 기대값과 이름을 갱신함. 실제 정확도 계산식 변경 없음.
- 최종 컴파일·테스트 결과: `Logs/PortfolioVerificationFix/`.
- 실제 UI Play 조작·커밋은 수행하지 않음.
