# 허위 포트폴리오 판정 진단

현재 수정 내역은 [수정 기록](허위_포트폴리오_판정_수정.md)에 정리함. 아래 내용은 수정 전 진단과 재현 기록임.

## 결론

- 허위 포트폴리오 존재 여부를 무작위로 배정하는 단계가 없음.
- 실제 품질이 `Good` 또는 `Normal`인 지원자에게는 항상 더 낮은 `FakePortfolioQuality`를 생성함.
- 질문 답변은 실제/허위 품질을 별도로 추첨하며, 결과 화면은 허위 품질 값의 존재 여부를 참조함.
- 세션의 검증 점수는 선택한 문서 줄과 `Applicant.Kind`를 참조함. 결과의 빨간 이름 표시와 다른 기준임.
- 따라서 좋음 답변·정상 종류 지원자·허위 포트폴리오 결과 표시의 공존을 재현함.

## 코드 경로

- [PortfolioQualityRule.cs](../Assets/Scripts/Interview/Data/PortfolioQualityRule.cs): `CreateFake`가 Good → Normal/Bad 무작위, Normal → Bad 고정, Bad → null을 반환함. 허위 유무 확률은 없음.
- [InterviewSession.cs](../Assets/Scripts/Interview/Rules/InterviewSession.cs): `CopyApplicants`에서 생성 값을 지원자 복사본에 저장함. 생성 후 읽기·결과 투영 과정에서 재추첨되지 않음.
- [QuestionController.cs](../Assets/Scripts/Interview/Runtime/QuestionController.cs): 포트폴리오 질문은 기본 50%로 저장된 허위 품질을 선택하고, 나머지는 실제 품질을 선택함. 응답은 지원자별 캐시됨.
- [SelectedTeamResultProjection.cs](../Assets/Scripts/Interview/Rules/SelectedTeamResultProjection.cs): 저장된 허위 품질 존재·실제 품질과의 차이로 `HasFalsePortfolio`를 설정함.
- [ResultBoard.Inspection.cs](../Assets/Scripts/Interview/Result/ResultBoard.Inspection.cs): `HasFalsePortfolio`에 따라 결과 이름을 빨간색으로 표시함.
- [VerificationRule.cs](../Assets/Scripts/Interview/Rules/VerificationRule.cs): 올바른 의심 줄이면 Success, 잘못된 선택이면 Failure, 선택이 없고 Kind가 Fraud면 Failure, 나머지는 None임.
- `InterviewSession.Accept/Reject`에서 이 검증 규칙을 실제 호출함.

## 실행 결과

### 품질 생성: 품질별 고정 시드 64회

- 실제 Good: 허위 Normal 31회, Bad 33회, 없음 0회.
- 실제 Normal: 허위 Bad 64회, 없음 0회.
- 실제 Bad: 허위 없음 64회.

### 세션·결과: 지원자 종류 × 실제 품질 9조합

- 종류 Normal/Fraud/Inappropriate 모두 실제 Good/Normal이면 결과 `HasFalsePortfolio=True`였음.
- 종류 Normal/Fraud/Inappropriate 모두 실제 Bad이면 결과 `HasFalsePortfolio=False`였음.
- 원본 지원자 불변, 세션 복사본 값 유지, 고정 시드 재현, 결과 생성 후 값 유지 확인함.
- 진단 조건 76개 확인함. 현재 동작을 확인하는 검사이며, 의도한 게임 규칙의 충족을 뜻하지 않음.

### 질문·검증: 고정 시드 재현

- 실제 Good + 저장된 허위 Normal인 지원자에게 실제 답변 선택 확률을 강제하면 Good 답변이 나옴.
- 기본 50% 설정, 시드 0~199: Good 답변 101회, 허위 Normal 답변 99회. 저장된 허위 상태는 유지됨.
- 종류 Normal: Good 답변과 허위 품질이 있어도 검증 결과 None임.
- 종류 Fraud: 동일한 Good 답변이어도 검증 결과 Failure임.
- 지원자 재바인딩 후 답변 캐시 유지 확인함.
- 진단 조건 7개 확인함.

### 기존 정확도 테스트

- `StageAccuracyRuleTests` 6개 실행: 통과 3개, 실패 3개.
- `NearRequirementRoundsTo87AndClears`: 기대 87, 실제 86.
- `MoreThanDoubleRequirementCapsThatSkillError`: 기대 67, 실제 66.
- `HalfwayAbove69RoundsAwayFromZeroTo70`: 기대 70, 실제 69.
- 현재 구현과 테스트의 반올림 기대가 불일치함. 허위 포트폴리오 문제와 별도 확인 필요함.

## 수정 방향

- 세션 생성 시 허위 존재 여부를 한 번 추첨하고 저장할 필요가 있음.
- 질문 설명·검증·결과 표시가 참조할 판정 기준을 통일할 필요가 있음.
- 현재 실제 품질·허위 품질 필드와 지원자 Kind의 의미를 구분하고, 추첨 확률과 질문에서 허위가 드러나는 규칙 확정 필요함.
- 원인 확인·테스트만 수행함. 판정 코드 수정·커밋 미진행함.
