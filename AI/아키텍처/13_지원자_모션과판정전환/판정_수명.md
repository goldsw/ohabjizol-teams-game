## 판정·논리 commit

1. Request: 비활성/Disposed/pending/Stage.IsDeciding 거부함. 완료 session은 즉시 RetryCompletion, 현재 지원자 없으면 거부함.
2. 현재 Applicant 참조·CurrentIndex·선택값 캡처 → IsPending=true·Changed 먼저 발행함. 연타·재진입 막음.
3. 질문 request 무효화·coroutine 중지 → manager.Accepted/Rejected callback 정확히 1회 호출함. 지원자·문서·초상 Clear하지 않음.
4. 반환 duration을 unscaled 시간으로 대기함. 대기 중 Session 판정·지원자 변경 이벤트·저장 호출하지 않음.
5. 종료 직전 generation·활성 상태·캡처 참조/인덱스·Session 미완료 검증 → Stage.Decide(선택값) 1회 호출함.
6. Stage.Decide의 기존 정리·판정·다음 바인딩·저장 완료까지 gate 유지 후 pending 해제·Changed 발행함.

- 논리 commit은 대기 종료 시점임. 대기 중 파괴는 미확정 선택 취소임. 마지막 Result는 대기 후 저장 성공한 경우에만 노출됨.
- DecisionRequested를 Stage.Decide 대신 coordinator.Request에 연결함. Runtime Ask/OpenDocuments/OpenCalendar도 pending 검사함.
- CompletionRetryRequested는 Runtime wrapper로 연결함. pending 중 반환, 이후 Stage.RetryCompletion 호출함.
- 저장 실패 상태의 합불 재시도는 callback·3초 대기 없이 실행함. 저장 실패 후 같은 지원자를 다시 판정하지 않음.
- Stage.IsDeciding은 기존 동기 guard임. 3초 gate는 coordinator 책임이며 Summary가 StateChanged로 재렌더되어도 blocked 유지함.

## 화면 수명·경합

- Disable: coordinator.Suspend로 generation 무효화·coroutine 중지·선택/잔여시간 보존 후 기존 질문 취소·문서 Suspend·구독 해제함.
- Enable: 이벤트 연결 → 현재 지원자/질문 Render → gate 복원 → Resume 순서임. pending 중 자동 RetryCompletion 건너뜀.
- Resume는 잔여시간만 대기하며 callback 재호출하지 않음. component 비활성 동안 시간·논리 진행 멈춤.
- Dispose: disposed·generation 갱신 → 대기 중지·pending 폐기 → 기존 ClearApplicant/문서 Dispose임. 오래된 iterator의 commit·바인딩·저장 금지함.
- CallView.OnDisable/질문 Render/Cancel의 SetAnswering(false)는 terminal 상태를 바꾸지 않음. component 비활성 순서와 무관하게 안전해야 함.
- SetDiscordVisible은 자식 패널 표시만 변경함. 접기 중 대기 계속함. screen component 비활성/파괴에 Suspend/Dispose 적용함.
- terminal 상태에서 manager.SetAnswering(true/false,tick) 무시함. 늦은 talk tick·취소·Render가 판정 포즈를 덮지 못하게 함.
- terminal 초기화: 새 지원자 Bind/Clear 또는 취소의 CancelDecision임. 같은 지원자 Render는 포즈·질문/문서/알림 상태 보존함.
- callback 예외·캡처 불일치: pending 취소함. gate 해제 시 현재 지원자 CancelDecision(Idle 복원) 후 재렌더함. 강제 advance 금지함.
- Stage.Decide 진입 전에 pending을 소비 상태로 표시해 재진입 막음. CompletionError/CompletionPending·저장은 기존 StageManager에 맡김.
