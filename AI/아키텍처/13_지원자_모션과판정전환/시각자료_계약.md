# 13. 지원자 모션과 판정 전환

상태: 구현·컴파일·에셋 연결 확인 완료함. Play 및 자동 테스트 미실행함.
소스 기준: `Assets/Scripts/Interview/`임.

## 요구·아트 인계

- 13개 태그 순서 = 스탯 profile `character-01`~`character-13` 순서임. 스탯 SO 13개 수정하지 않음.
- 프레임 1~4 = Idle/Talk/Accepted/Rejected임. state별 1포즈임.
- Talk는 기존 0.5초 tick Idle/Talk 교대임. 합불 callback이 반환한 시간(일단 3초) 동안 판정 포즈 유지 후 다음 지원자로 이동함.
- 마지막 지원자도 같은 대기 후 기존 결과·저장·씬 인계 경로 실행함.
- 아트 담당 산출: `Assets/Art/Applicants/character-01..13/{idle,talk,accepted,rejected}.png` 52개, 각 57×66 RGBA임.
- 원본: `Assets/Art/Applicants/Source/CUSTOMIZING.aseprite`임. `Assets/Art/Applicants/characters.json`에 tag/id/frame path·순서 기록함.
- 숨김 Background 제외·가시 4레이어 normal/opacity255·linked cel 6개 해석은 별도 아트 담당임.
- visual 담당의 작은 Editor bake가 Single Sprite/Point/무압축/mipmap 비활성 및 초상화 preserveAspect 적용함.
- Unity2D.Aseprite·2D.Sprite 미설치: 부모 확인됨. 패키지 추가·아트 재export 금지함.

## 확인된 원인

- `UI/InterviewScreen.cs:61` → `Runtime/InterviewRuntime.cs:70` → `Runtime/StageManager.cs:44`로 합불 요청 전달함.
- StageManager:52~55: ApplicantChanging → Session.Accept/Reject → ApplicantChanged → RetryCompletion을 동기 실행함.
- Runtime ClearApplicant(130행)가 질문·초상을 지우고 BindApplicant(137행)가 다음 지원자를 즉시 바인딩함. 대기 지점 없음.
- InterviewApplicantPresenter:31은 Bind(applicant)만 호출함. 캐릭터별 시각 자료·판정 상태 관리 없음.
- InterviewCallView 51행은 공통 idle/talk Sprite를 교체함. QuestionPresenter 취소·tick·종료도 이를 호출해 판정 포즈를 덮을 수 있음.
- `Data/Applicant.cs:67`에 CharacterId가 이미 있음. 도메인에 Sprite 추가 불필요함.

## 책임·공유 API

- StageManager·Session 동기 판정·저장 유지함. StageManager 지연 interface 대신 Runtime 앞단 coordinator 선택함.
- 새 `Runtime/InterviewDecisionCoordinator.cs`: 화면 host coroutine·unscaledDeltaTime·입력 gate·취소 세대·잔여시간 소유함.
- 기존 InterviewApplicantPresenter를 현재 지원자 manager로 사용함. 지원자·Idle/Talk/Accepted/Rejected 상태·합불 callback을 소유함.
- 새 `Unity/ApplicantVisualCatalog.cs`: 명시적 serialized CharacterId→visual entry 매핑 SO임. entry에 Sprite 4개·합불 duration(각 3f) 보유함.
- `ApplicantVisualCatalog.TryGet(string characterId, out ApplicantVisualDefinition visual) : bool` 계약임.
- definition 공개 읽기 property: `Idle`, `Talk`, `Accepted`, `Rejected`, `AcceptedDuration`, `RejectedDuration`임.
- catalog는 ID 정확 일치로 조회함. 이름·직군·등장/Sprite 순서 추론 금지함.
- InterviewCallView에 serialized `_visualCatalog`·읽기 전용 `VisualCatalog` 추가함. presenter가 기존 call 참조로 취득함.
- 누락 ID/시각 자료는 placeholder·로그 처리함. 다른 캐릭터 대체 금지·null ID도 기본 3초임.
- bake가 13개 ID 중복/누락·Sprite 4개·manifest 대응 검증함. manifest는 Editor 입력이며 런타임 파일 로딩하지 않음.
- `ApplicantMotionState { Idle, Talk, Accepted, Rejected }`: InterviewApplicantPresenter.cs에 namespace 수준 enum으로 정의함.
- presenter 추가 API: `State { get; }`, `Accepted() : float`, `Rejected() : float`, `SetAnswering(bool answering, int tick) : void`, `CancelDecision() : void`임.
- callback은 terminal 상태·포즈 적용 후 duration 반환함. duration은 유한·0 이상, 그 외 3f임.
- view 추가 API: `SetPose(Sprite sprite) : void`임. 기존 SetAnswering(bool,int)는 말풍선·점만 갱신하도록 Sprite 쓰기 제거함.
- question 생성자 말미에 `InterviewApplicantPresenter applicant = null` 추가함. answering helper가 말풍선·manager에 전달함.
- question presenter 추가 API: `SetInputBlocked(bool blocked) : void`임. Ask/Render/radial/질문 버튼 모두 같은 gate 적용함.
- summary presenter 추가 API: `SetInputBlocked(bool blocked) : void`임. Render의 버튼 open/retry 조건에 gate 적용함.
- coordinator 생성자: `(MonoBehaviour host, StageManager stage, Func<bool,float> presentDecision)`임.
- coordinator API: `Request(bool accepted)`, `Suspend()`, `Resume()`, `Dispose()`, `bool IsPending { get; }`, `event Action Changed`임.
- Runtime presentDecision: questionView.Cancel() 후 accepted ? applicant.Accepted() : applicant.Rejected()를 반환함.
- Changed는 두 presenter.SetInputBlocked 동기 갱신함. Create는 question에 applicant 전달함.
