# 진행 저장 구조
## 기록 종류
- StageProgressStore: 누적 클리어 여부와 최고 정확도 담당함. v2 레코드는 스테이지 이름 ID로 저장함.
- CampaignRunStore: 회차 ID·4스테이지 완료·정확도·엔딩 점수 담당함. v1 회차 데이터와 RunId를 읽음.
- StageCompletionService: 완료 요청의 검증·저널·두 기록 적용·중복 방지·복구 담당함.
- ResultSceneEntry: 전달된 결과를 표시함. 결과 씬 진입 시 진행을 기록하지 않음.

## 이전 기록
- v1 배열은 EntranceGameJam/GameProgrammingIntro/SecondYear/ThirdYear 고정 순서로 변환함.
- 정상 부분 기록은 보존하고 누락 점수는 -1로 생성함. v1 원본과 변환 백업을 남김.
- v2 로드의 중복 ID는 clear OR·best 최대값으로 병합함. 현재 미지원 ID는 활성 도메인에 적용하지 않음.
- 미래 버전·손상된 v2는 예외로 보고하고 원본을 덮어쓰지 않음.
- v2/완료 ID 해석은 현재 enum을 사용함. 도메인의 현재 스테이지 용량은 4이며, 스테이지 추가 시 도메인 용량도 확장해야 함.

## 완료와 복구
- Complete(runId,result): 현재 회차·스테이지·점수 확인 → 저널 저장 → 누적 진행 저장 → 회차 저장 → 저널 제거 순서임.
- 동일 회차·스테이지·점수의 재시도는 중복 점수나 추가 진행을 만들지 않음. 다른 점수·다른 회차는 저장 전에 거부함.
- RecoverPending은 두 저장의 중간 상태를 재적용함. 같은 결과가 이미 반영된 상태도 정상 처리함.
- 다른 회차 저널은 폐기하여 새 회차를 오염시키지 않음. 손상 저널·현재 회차 부재는 예외로 진입 중단함.
- Load/StartNewRun에서 복구하며 내부 LoadWithoutRecovery로 재귀를 피함.
- 두 저장의 순차 호출은 원자적 트랜잭션이 아님. PlayerPrefs 저장 실패를 예외로 관측할 수 있는 범위에서 오류를 보고함.

## 검증 경계
- PersistenceKeys는 v1/v2/변환 백업/campaign/저널 키를 제공함.
- 검증은 키 존재 여부·원래 값을 복원하고 새로 생긴 검증 키를 제거함.
- 누적 70% 클리어와 회차 완료의 실패 진행은 서로 다른 의미임. 실패도 회차 완료로 다음 스테이지에 진행함.
