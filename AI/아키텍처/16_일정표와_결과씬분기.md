## 일정표 표시

- 입학 게임잼 정원6명. 일정 처리와 렌더는 전체 참가자를 순회함. 데이터의 Take(4) 제한 없음.
- 고정 viewport·RectMask2D 및 세로 스크롤 때문에 아래 참가자 행이 가려짐.
- 헤더1행 + 제작 일정1행 + 참가자6행 = 8행을 viewport 안에 맞춤함.
- 이름과 날짜 열의 글자 크기·행간을 동일하게 계산함. 세로 스크롤 해제, 가로 스크롤 유지함.
- 프리팹과 기존 씬의 authored UI에도 동일한 배치 적용함. 참가자 데이터를 삭제하거나 4명으로 줄이지 않음.
- 제목·선택자6줄·별·디버그·일정의 고정 영역은 Editor BakeInspectionUi에서만 배치함. Play에서 저장된 RectTransform 위치를 다시 강제하지 않음.
- runtime FitScheduleLayout은 viewport 내부의 행 높이·공통 폰트·콘텐츠 크기만 계산함. 에디터에서 수정한 배치 유지함.
- 선택자 좌측 .04~.28 / y .618~.84, debug 우측 .71~.98 / y .60~.85, 별 중앙 .30~.675 / y .71~.83, 총점 중앙 y .59~.69로 분리함. 일정 영역 .04,.11~.96,.58 유지함.
- 새 씬 Theme는 기본 brown 글자와 어두운 무채색만 밝게 보정함. 버튼 자손 제외로 기존 밝은 버튼의 어두운 글자 유지, 빨강·금색 유지함.

- 추가 원인: 기존 ResultScene에는 authoredRoot 아래 ResultSchedule이 2개(각 Text32개) 존재했음. 총 Text85개이며, board에 연결되지 않은 이전 패널의 '일정 정보 없음'이 결과 요약과 겹쳐 출력됨.
- NormalizeAuthored에서 유효한 scheduleRoot가 있는 ResultBoard만 대상으로 같은 부모·같은 이름의 연결되지 않은 패널을 비활성 보존함. 연결 패널·데이터·기존 오브젝트는 삭제하지 않음. prefab instance 활성 상태 override도 기록함.

## 일정 점수 의견 — 이번에는 미적용

- 제안식 `30 / (30 - 30*(해당일 불참인원/6)) = 1/(1-불참비율)`은 지연배율임. 1명 불참이면 1.2배, 전원 불참이면 분모0임.
- 별점에 쓸 값은 반대 방향인 일정 충족률 권장함. 실제 제작일 수 D, 날짜별 참석인원 a[d]일 때 `C = Σa[d] / (6*D)`임.
- 30칸 중 프로젝트가 제작일로 표시한 날짜만 집계함. 비제작일 불참은 제외함.
- 제작15일 중 1명이 하루 불참하면 C=89/90=98.89%, 지연배율90/89≈1.011임.
- D=0은 일정 미설정, 제작일이 있으나 전원 불참이면 충족률0·지연배율 산정 불가로 취급 권장함.
- 추후 별점 반영 승인 시 `스탯 정확도*C`를 마지막에 한 번만 기존 반개별 floor 규칙으로 변환하는 방식 검토 가능함.
- 기존 floor 규칙상 작은 일정 손실도 5별→4.5별이 될 수 있음. 점수 가중치·참가자 미충원 처리와 함께 별도 결정 필요함.
- 이번 요청은 의견 요청이므로 점수·클리어·엔딩 임계값 계산 변경 없음.

## 결과 씬 계약

- `ResultSceneRoute.For(InterviewResult)`가 이번 단계 결과의 HalfStarUnits로 씬 이름을 결정함.
- 9이상(4.5별) GoodResultScene, 7이상(3.5별) NormalResultScene, 나머지 BadResultScene. null은 기존 ResultScene으로 진입함.
- 세 씬은 동일 ResultBoard·ResultSceneEntry·결과 데이터·일정표·버튼을 사용함. 배경 Image 색은 초록·노랑·빨강 계열로 구분함.
- 새 씬 공통 글자 대비 보정은 동일하게 적용함. 기존 ResultScene은 보존함.
- `InterviewExit`에서 결과 전달 후 공통 라우터를 사용함. 빌드 씬에 새3개를 추가하고 기존 씬 설정은 보존함.
- `ResultPresentationBake.Apply()`가 새 씬과 직렬화된 UI를 재생성/정규화함. `InterviewRefreshBake`도 같은 결과 씬 목록을 유지함.
- 결과 화면의 Continue는 기존 캠페인 누적 엔딩 판정 유지함. Good/Normal/BadEndingScene은 결과 씬과 별도로 보존함.
