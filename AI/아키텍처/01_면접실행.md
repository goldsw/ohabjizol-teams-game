# 면접 실행 구조
## 상태 소유자
- StageContext: 진입 시 확정된 RunId·StageDefinition과 지원자 문서키 담당함.
- StageManager: InterviewSession 수명·판정·지원자 전환·완료·완료 재시도 담당함. 순수 C# 객체이며 화면 활성 상태와 수명을 구분함.
- InterviewSession: 커서·팀·검증·능력치·점수 계산 담당함. 도메인 규칙을 화면에서 계산하지 않음.
- QuestionController: 질문 예약·완료·취소와 요청 유효성 담당함. 취소된 요청은 답변을 확정할 수 없음.

## 구성과 입력
- InterviewRuntime.Create: 미완료 저장 복구 → 회차·스테이지 확정 → 세션·기능 구성 순서임.
- InterviewViewReferences: 기존 Inspector 참조를 묶고 배열을 복사함.
- InterviewScreen: 요청 이벤트·직렬화 참조·공개 호환 조회·수명 연결 담당함. UI 생성은 InterviewScreen.Authoring의 EditMode Bake로 분리됨.
- Screen 요청 → InterviewRuntime 연결 → 상태 소유자 처리 → presenter/view 표시 흐름임.
- OnEnable에서 구독·최초 시작 또는 현재 상태 표시함. OnDisable에서 질문 취소·패널 숨김·구독 해제함. OnDestroy에서 문서를 정리함.

## 기능별 표시
- InterviewQuestionPresenter: 3초 응답 모션·점 말풍선·대사·질문 버튼 표시 담당함.
- InterviewApplicantPresenter: 지원자 표시·문서키·포트폴리오 표시 상태 담당함. 재활성화 시 같은 지원자를 새로 생성하지 않음.
- InterviewDocumentPresenter: DocumentWorkspace의 다운로드·PDF·고정 문서함 수명 연결 담당함. [스테이지 문서함](05_문서함.md) 참조함.
- InterviewNotificationPresenter: 새 서류 알림·읽음 상태 담당함.
- InterviewSummaryPresenter: 현재/요구 스탯·팀 슬롯·버튼·완료 상태 표시 담당함.

## 판정과 완료
- 판정 전 이전 응답·문서·알림을 정리하고 다음 지원자 상태를 표시함. 질문을 모두 사용하지 않아도 판정 가능함.
- 질문 사용 수는 응답 중 예약을 포함함. 취소된 예약은 복구하며 완료된 응답은 화면 비활성화로 지우지 않음.
- 완료 저장에 성공한 결과만 Result/HandoffSceneName으로 노출함.
- 완료 실패는 완료 대기 상태로 유지함. RetryCompletion·재활성화·판정 버튼의 재시도 경로를 제공함.
- 기존 사운드용 Ohabjizol.Managers.StageManager와 면접용 Ohabjizol.Interview.StageManager는 다른 책임임.
