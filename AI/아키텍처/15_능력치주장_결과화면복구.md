# 능력치 주장과 결과 화면 복구

- 기준: 2026-10-18 사용자 수정 요청. 이전 허위 스탯 표시 계약을 아래 기준으로 대체함.
- 선행 변경 커밋: `d457bf22e35ef82830012f424462cfbfc7c0f8a6`.

## 능력치 계약

- 지원자 프로필 13개. 각 프로필은 기획·프로그래밍·아트 3직군 중 하나를 무작위 선택함.
- 선택한 직군 행의 최소·최대 범위에서 각 능력치를 정수로 추출함. 양 끝값 포함, 스테이지별 직군 수 균등 배분은 보장하지 않음.
- `ExpectedSkills`: 정상 행에서 추출한 주장 능력치. 별로 표시하는 예상 능력치의 유일한 출처임.
- `FakeSkills`: 허위 행에서 추출한 실제 능력치. 허위 행이 없는 경우 null, 빈 셀은 동일하게 추출된 정상값 사용함.
- `ActualSkills`: `FakeSkills ?? ExpectedSkills`. 합격 팀의 실제 평가에 사용함.
- `DisplayedSkills`: `ExpectedSkills`. 허위 지원자도 정상 행의 별 표시를 사용함.
- 범위가 겹칠 수 있으므로 추출 뒤 허위값을 정상값보다 작게 강제하지 않음. 표의 확률 분포 유지함.
- 포트폴리오의 진짜·가짜 품질 태그 및 결과창 빨간색 표시 조건은 별도 계약 유지함.
- 캐릭터08 아트: 정상 기획1~3·프로그래밍2~6·아트7~10, 허위 실제 기획1~2·프로그래밍1~4·아트2~7 확인함.

## 결과 화면 원인과 조치

- ResultScene 진입 및 ResultBoard 결과 데이터·주요 텍스트 참조 정상 확인함.
- 기존 `ResultOverlay`와 신규 `AuthoredUi`의 sortingOrder가 모두 0임. Play에서 기존 패널 renderOrder1, 신규 UI renderOrder0으로 기존 패널이 위를 덮음.
- 신규 일정표의 Summary·Names·Day01~30 텍스트 총32개에 폰트 참조 누락 확인함.
- 기존 ResultOverlay 오브젝트는 보존하고 비활성화함. 신규 결과·엔딩 Canvas sortingOrder100으로 저장함.
- 결과·엔딩 씬 및 결과 프리팹의 모든 authored Text에 영속 NotoSansKR.ttf 에셋 연결함. 임시 생성 Sprite 참조는 제거함.
- `ResultPresentationBake.Apply()`가 위 조건을 재적용함. 씬·프리팹을 에디터 편집 가능한 직렬화 데이터로 유지함.
