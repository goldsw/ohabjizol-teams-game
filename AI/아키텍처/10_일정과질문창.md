# 일정·질문창 통합 설계
갱신일: 2026-10-15 · 통합 컴파일·Bake 완료 / Play·시각 확인 미실행 / 커밋 결과는 채팅의 커밋 식별자 참조함.

## 상태와 근거
- 데이터·규칙·연결 런타임 API는 소스 직접 대조 완료함. 부모 Solhigh 리뷰는 추가 presenter 3개 포함 확정 결함 없음, true 품질·세션 복제본 소비 일치 확인 보고임.
- 부모 최종 보고: Unity recompile_status=completed, failed=false, errors=[], compilationFailed=false임.
- RadialQuestionBake.Apply(InterviewScreen.prefab) 저장 성공함. 직렬화: Windows=1, FixedLaunchers=1, Questions=5, Rotation=100, OptionsParent=Info, MissingScripts=0임.
- Wallpaper 프리팹 읽기: Wallpaper=1, MissingScripts=0임. 결과씬 Bake 저장 성공·boards=1임.
- UI·런처 통합 상태는 부모 최종 보고 기준임. 직렬화 확인과 Play 동작·실제 시각적 배치 확인은 구분함.
- 설계 당시 graphify 30초 무응답으로 기존 로컬 JSON 참고함. 판단 근거는 현재 소스임. 토큰 절감량 미측정임.

## 원인: 설계 시점 기록
- Download는 문서함 갱신만 수행함. OpenDocument의 동일 키 창 존재 시 no-op은 유지 요구임.
- RadialQuestionView launcher가 옵션을 직접 토글하고 상시 앱 책임은 없었음.
- StageCalendarState 독립 Random·UI 조건부 생성으로 지원자·Q2·결과의 공유 일정 계약 없었음.
- Applicant fake 검증은 품질 차이만 확인함. 최하은 actual Bad / fake Good은 요구 위반이었음.
- Desktop.prefab Wallpaper에 m_Script fileID 0·DesktopBackground 식별자 확인함. 소스/meta 부재·Image 존재·MainMenuScene 이름 override는 부모 Luna 보고임.

## 데이터 API: 구현 완료
- MonthlySchedule은 readonly struct, true는 generic marker임. 불가일·제작일 의미는 사용처가 정함.
- MonthlySchedule(bool[] days): null 거부·길이 30 요구·배열 복제함. 내부 배열 외부 노출 없음.
- IsMarked(int day1based): 1~30 조회, 범위 밖 ArgumentOutOfRangeException임.
- GetMarkedDays(): 1-based 오름차순 int[] 새 복사본 반환함. Count는 표시일 수임.
- static CreateRandom(int count, System.Random random): count 0~30·중복 없는 날짜, null random 거부함.
- default(MonthlySchedule)은 안전한 빈 일정임. Count=0, 유효일 IsMarked=false, GetMarkedDays() 빈 배열임. nullable·재추첨 없음.
- struct 대입은 내부 배열 깊은 복사가 아님. 입력 복제·외부 변경 차단으로 불변성 유지함. 향후 참조형 원소 추가 시 원소 복사 필요함.
- Applicant.UnavailableSchedule: MonthlySchedule임. 생성자 끝 선택 인수 unavailableSchedule=default(MonthlySchedule) 추가, 기존 호출 호환함.
- PortfolioQualityRule.Rank(PortfolioDisplayState quality): Bad=0 < Normal=1 < Good=2, enum 숫자 순서 독립임.
- PortfolioQualityRule.CreateFake(PortfolioDisplayState actual, Random random): Bad→null, Normal→Bad, Good→Normal/Bad 무작위임.
- Applicant는 fake가 actual보다 엄격히 나쁨을 검증함. 최하은 actual Bad 유지·불법 fake 제거함.
- InterviewResult.ScheduleResult: InterviewScheduleResult임. 마지막 선택 인수 scheduleResult=null 생략 시 빈 결과 제공함.
- InterviewScheduleResult(MonthlySchedule projectSchedule, IReadOnlyList<ParticipantScheduleResult> participants) 생성자 제공함.
- 해당 속성: ProjectSchedule: MonthlySchedule, Participants: IReadOnlyList<ParticipantScheduleResult>, ConflictingDays: IReadOnlyList<int>임.
- ParticipantScheduleResult(string applicantName, MonthlySchedule unavailableSchedule, MonthlySchedule projectSchedule) 생성자 제공함.
- 해당 속성: ApplicantName: string, UnavailableSchedule: MonthlySchedule, ConflictDays: IReadOnlyList<int>임.
- Participants 입력 복사·읽기 전용 출력함. 충돌 날짜는 1~30 오름차순·중복 없음. 이름은 표시용, 연결은 세션 객체 사용함.

## 세션과 일정: 구현 완료
- InterviewSession(StageDefinition stage, int productionDays, Random random=null) 추가함. 기존 생성자 유지함.
- InterviewSession.ProjectSchedule: MonthlySchedule, internal RandomSource: Random 제공함.
- StageManager(StageContext context, Action<string, InterviewResult> complete, int productionDays, Random random=null) 추가함. 기존 생성자 유지함.
- QuestionController(float fakeAnswerChance, Random random) 추가함. 기존 기본 확률 0.5 생성자 유지함.
- InterviewRuntime.Create가 StageScheduleConfig.GetProductionDays(definition.Id) 전달함. 설정 없으면 15일, UI 없이도 세션에서 생성함.
- 프로젝트 일정·지원자별 1~2 불가일·모든 eligible fake 후보를 세션 생성 시 한 번 확정함. Applicant 복제, 정적 template 변경 없음.
- QuestionController는 세션 난수원 공유·Applicant 객체별 응답 캐시 사용함. 동일 컨트롤러 재바인딩·질문 취소 후 재질문 시 재추첨 없음.
- Q2는 Applicant.UnavailableSchedule.GetMarkedDays() 사용함. [12,20] → “12일, 20일은 일정이 안된다고 하였다.”임. 빈 일정도 처리함.
- StageCalendarState(MonthlySchedule projectSchedule), ProjectSchedule 추가함. 기존 int 생성자·ProductionDays·DatesReadonly·ProductionDates·IsProductionDay 유지함.
- Runtime 캘린더 바인딩은 세션 ProjectSchedule 어댑터 사용함. 재활성화·재표시·완료 저장 재시도 시 일정 재생성 없음.
- 실제 포트폴리오 그림 유지함. fake는 설명 품질 후보에만 적용하며 기존 9대사·debug prefix 변경 없음.

## 합격자·결과·저장: 구현 완료
- InterviewSession.BuildScheduleResult는 최종 Team.Members[i].Applicant에서 참여 명단 확정함. Accept 횟수·현재 지원자 기준 아님.
- ConflictDays = ProjectSchedule && UnavailableSchedule인 날짜, ConflictingDays = 전체 참여자 충돌 합집합임.
- 참여 가능 겹침은 ProjectSchedule && !UnavailableSchedule로 도출 가능함.
- BuildResult가 일정 snapshot 포함함. 기존 능력·등급·클리어·점수 계산 유지함.
- StageManager는 저장 성공 후 Result 공개함. 완료 재시도는 같은 결과 사용함.
- ResultCarry.Take → ResultSceneEntry.Start → ResultBoard.Show(InterviewResult) 전달 경로 유지함.
- ResultBoard는 ScheduleResult 표시함. 난수 생성·전역 일정 재조회 책임 없음. 기존 동시 작업 변경 보존함.
- 부모 Luna 조사: 저장·복구는 stage ID·accuracy 중심, InterviewResult 전체 재구성 DTO 없음. schema 확장 없음·프로세스 간 일정 복원 제공하지 않음.

## 다운로드·문서창: 통합 계약
- Download 저장 성공 직후 저장된 DocumentKey로 OpenDocument 호출함. 비동기라면 시작 시 지원자 키·문서 snapshot 사용함.
- 동일 키 창 존재 시 완전 no-op임. 복원·전면화 없음. 미등록 키만 창 생성함.
- 최소화 복원은 작업표시줄에서만 수행함. 문서함 재클릭에도 중복 no-op·다른 창 유지함.

## 질문창·런처: 통합 계약
- fixed는 작업표시줄 상시 앱 아이콘임. 드래그·위치 고정 의미 아님.
- 질문 5개·sin/cos 원형 배치·초당 100도·unscaledDeltaTime 유지함.
- 단일 호스트·안정적 앱 ID 사용함. 닫기·최소화·지원자 교체에도 아이콘 유지, 화면 수명 종료 시 구독·등록 해제함.
- launcher와 작업표시줄은 동일 호스트 명령 사용함. 기존 ToggleExpanded 직접 구독 해제로 이중 처리 방지함.
- 호스트는 가시성·최소화·복원, RadialQuestionView는 배치·회전·버튼 상태 소유함.
- 지원자 부재·응답 중 질문 버튼 상태와 앱 아이콘 존재 분리함. ResetCollapsed/SetAvailable 관련 실행 동작은 Play 후속 확인 대상임.

## Wallpaper: 통합 반영
- 끊긴 컴포넌트 블록·m_Component 항목만 참조 확인 후 제거함. Image·MainMenuScene AuthoredDesktopRoot 이름 override 유지함. 전체 Bake 금지함.

## 검증 상태·부모 후속 확인
- 데이터 API·default·배열 복제·컬렉션 보호·최종 명단 참조는 소스 대조 완료함. 실행 테스트 미실행임.
- 최종 Unity 컴파일·radial 프리팹 Bake·결과씬 Bake 저장 및 위 직렬화 값 확인 완료함. 근거는 부모 보고임.
- 런타임 Play 테스트 미실행·실제 시각적 배치 확인 미실행임. 질문 상시 아이콘·단일 호스트·launcher·회전은 실행 후속 확인 대상임.
- 후속: 다운로드 자동 열기·동일 문서 no-op·작업표시줄 전용 복원 확인 필요함.
- 후속: 세션 일정·Q2·fake·참여 명단·충돌 합집합·결과 전달·완료 재시도 확인 필요함.
- Wallpaper 읽기 MissingScripts=0 확인함. Wallpaper 한정 변경·전체 Bake 미수행 계약 유지함.
- 커밋은 다음 단계 예정·현재 미완료임. 이 문서 갱신에서는 커밋 수행하지 않음.
- 이번 갱신은 Markdown만 수정함. 컴파일·Bake·테스트 직접 실행 없음. 부모가 후속 검증 결과를 이 절에 추가함.
