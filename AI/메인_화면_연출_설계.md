# 메인 화면 연출 설계

- 승인된 구조 설계 · 2026-10-19. 구현 현황은 [적용 기록](메인_화면_연출_적용.md) 참조함.
- 최초 설계 단계에서는 문서만 작성했으며, 실제 씬 적용 여부는 적용 기록에서 구분함.
- [탐색 기록](../Logs/MainMenuArchitecture/inventory.md)·지정 코드와 기존 Graphify 질의 결과를 근거로 작성함.

## 현재 → 제안

- 현재: 접근 → 부팅 → Desktop → AlignToCenter → RememberPose → LoadingScene Single → Interview 로딩·완료 표시·줌·활성화임.
- 문제: pose 저장은 책상·Canvas 생존 보장 불가함. authored pose의 look lock은 Desktop 미세회전 요구와 충돌함.
- 확정: MainMenuController 단일 상태 소유 + SceneLaunchFlow 공통 추출 + 기존 camera 확장 + World Space ComputerScreen 재사용함.
- 메인 환경에서 로딩·줌 후 InterviewScene 활성화함. LoadingScene은 기존 진입 adapter로 유지함.
- 추가 패키지·신규 모델 제작 없음 전제임. 관측 환경 Unity 6000.3.15f1 / URP / Aseprite 3.0.2임.

- 기존 MainMenu3D/Zooming/Booting/DesktopReady/Launching 유지, 이후 Loading/FillZoom/Activating 확장함.

- CampaignRunStore.Load·StageSelection.Set·StartNewRun은 MainMenuController 소유임. 캠페인 완료 endingScene Single 분기 유지함.
- 요청의 GameScene은 현행 InterviewScene에 대응함. 원경·Desktop 미세회전, 실행 정렬 완료 이후 고정함.

## 책임·API 계약

- 아래 API 변경은 향후 계약임. 구현 완료 의미 아님.
- MainMenuController: Phase·입력·순서 소유함. Bind(connectDelay, Launch), MonitorClicked, Launch(StageId), Play, Ready 재사용함.
- 호출: Launch → Desktop.Lock → AlignToCenter 완료 → Flow.TryStart → 로딩 표시 → CanBeginZoom → transition.Begin → Flow.TryActivate임.
- SceneLaunchFlow 신규: 기존 AsyncOperation·최소 시간·표시 진행률·완료 유지·활성화 추출함. 카메라·메뉴 상태 소유 없음.
- Flow 계약: TryStart(sceneName, out error), Tick(unscaledDeltaTime), Snapshot, CanBeginZoom, TryActivate임. 시작·활성화 각각 1회임.
- LoadingUiPresenter 최소 추출: 기존 UI 생성·참조·문구·바 재사용, Render(Snapshot) 담당함. 씬·카메라 제어 없음.
- MainMenu와 LoadingSceneController가 같은 Flow/Presenter 사용함. 후자는 독립 진입 adapter이며 메인 경로에서 실행 안 함.
- MainMenuCameraController: 기본 포즈·mouse offset·FOV의 유일한 writer임. SetAuthoredPose/MoveToAuthoredPose/AlignToCenter 확장함.
- SetLookEnabled(bool) 추가함. 원경·부팅·Desktop 활성, 접근은 기본 포즈와 미세회전 합성, 실행 정렬부터 offset 감쇠 후 잠금함.
- AlignToCenter(Action): offset을 0으로 보간하고 화면 법선 중앙으로 정렬, 거리·FOV 유지 후 콜백 1회임.
- ComputerTransitionController: CenterAndLock·Begin(Action)·fill 계산 재사용함. 직접 transform/FOV 쓰기를 카메라 명령으로 이관함.
- Begin은 목표 포즈·FOV·duration·curve 전달 담당함. 새 coordinator·카메라 writer 추가 없음.
- ComputerScreen: frame·ViewRoot·PlaceWorldCanvas 배치 기준 재사용함.
- DesktopView: prefab Bind/RefreshAuthoredContent/Lock 재사용, runtime Build 금지함. 실제 _generatedDesktopRoot 유지함.
- MonitorClickHandler: 기존 좌클릭 전달만 담당함.

## 제안 씬 계층·생존

~~~text
MainMenuScene
 ├─ MainMenuController / Flow 구동 / LoadingUiPresenter
 ├─ CameraPoseRoot
 │   └─ MouseLookPivot
 │       └─ Main Camera + MainMenuCameraController + PhysicsRaycaster
 ├─ CameraAnchors (introStart / zoomTarget / 중앙 기준)
 ├─ RoomBackground / DeskRoot(FBX)
 │   └─ MonitorRoot: ComputerScreen / ScreenFrame / 클릭 Collider / 후광
 │       └─ MonitorWorldSpaceCanvas + GraphicRaycaster
 │           ├─ Wallpaper / Desktop prefab
 │           └─ BootOverlay / 기존 Loading UI
 └─ EventSystem + 기존 input module
~~~

- 같은 메인 환경·카메라·World Canvas를 로딩·완료 유지·줌과 활성화 직전까지 유지함.
- InterviewScene을 Single/allowSceneActivation=false로 준비, TryActivate에서만 true로 전환함.
- DDOL 환경 복제·LoadingScene 카메라 중복 없음. RememberPose/ApplyFixedPose는 레거시 호환 전용임.
- 기존 sceneLoaded의 ComputerScreen.ViewRoot 제거는 레거시 부작용임. 대상 씬·루트 명시 후 1회 처리, 메인 경로에 무조건 복제 금지함.
- 컨트롤러는 Camera에 유지, GetComponent<Camera>() 계약 보존함. rig/pivot은 serialized 참조임.

## 입력·전환 가드

- 모니터 좌클릭 1회, Desktop 아이콘 더블클릭 유지함. 요청의 ‘클릭’을 단일 클릭 실행 변경으로 해석하지 않음.
- MainMenu3D만 PhysicsRaycaster/Collider 허용, DesktopReady만 UI 입력 허용함. Boot/Loading은 표시 전용임.
- Canvas.worldCamera에 메뉴 카메라를 지정하고 GraphicRaycaster.eventCamera 일치를 확인함. 책상 Collider의 UI 차단은 layer/blocking으로 분리함.
- _accepted·Phase로 중복 실행 차단함. UI 잠금·완료 콜백 1회·disable 이후 콜백 차단 계약임.
- 로드 전 씬 등록·참조·frame·EventSystem·UI 검증함. 실패 시 진행 중단·오류 표시함.
- 보류 AsyncOperation은 실제 취소·반환 미지원임. 시작 후 입력 잠금, 취소·메뉴 복귀·중복 로드 약속 금지함.
- 시작 이후 오류는 잠금·오류 표시 유지함. 임의 활성화·추가 로드로 복구하지 않음.
- 부팅 progress는 duration 기반 연출임. 실제 로드는 progress/0.9·최소 시간·표시 보간 충족 → 100%·완료 유지 → 줌 → 활성화임.
- 완료 표시는 게임 초기화 완료 의미 아님. 카메라·Flow는 unscaled 시간 사용함.
