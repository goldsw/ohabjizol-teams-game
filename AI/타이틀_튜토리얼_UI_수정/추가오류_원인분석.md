# 튜토리얼·게임 진입·작업표시줄 추가 오류 분석

## 조사 범위

- Graphify 기존 그래프 → 관련 코드 → 저장된 프리팹/씬의 실제 오브젝트 순서로 확인함.
- Unity Play 중지 상태에서 정적 조사만 수행함. MainMenuScene은 임시 PreviewScene으로 읽고 닫음.
- 사용자 추가 조건: 문서함 안내 단계 이전까지 작업표시줄 배치 정상이었음.
- 본문 원인 분석은 수정 전 상태 기준임. 후속 적용 상태는 문서 하단 참고.

## 1. 튜토리얼 아이콘 미표시

**원인: MainMenuScene의 튜토리얼 아이콘이 비활성화되어 있음.**

- 공통 Desktop.prefab의 `Desktop/Icons/TutorialIcon`: `activeSelf=true`.
- MainMenuScene의 실제 `MainMenu/.../ComputerScreen/MenuScreenCanvas/AuthoredDesktopRoot/Icons/TutorialIcon`: `activeSelf=false`.
- 아이콘 자체 누락이 아니라 프리팹과 씬 인스턴스의 활성 상태가 다름.
- 루트 Image의 sprite=null/alpha=0은 원인이 아님. 실제 표시는 자식 Tile/Glyph/Label이 담당하며 각각 존재함.
- 튜토리얼 창에는 Start/Skip 버튼 참조가 연결되어 있음. 창이 처음 닫혀 있는 것은 정상임.
- 수정안: 씬 인스턴스의 TutorialIcon 비활성 오버라이드 해제/활성화. 튜토리얼 실행 바인딩은 유지함.

관련: [MainMenuScene](../../Assets/Scenes/MainMenuScene.unity), [Desktop 프리팹](../../Assets/Prefabs/InterviewRefresh/Desktop.prefab).

## 2. 청강코드 → 새 게임 진입

**원인: 자동 연결은 앱 아이콘에, 새 실행 초기화는 새 게임 버튼에 분리되어 있음.**

- `DesktopAppBinding.cs`의 `ChungkangCodeAppHandler.Activate()`는 창을 열자마자 `code.Connect(..., context.Launch)`를 호출함.
- `ChungkangCodeWindow.NewGame()`은 `ResetConnection → StartNewRun → Refresh → RunReset`만 수행함.
- `RunReset` 수신자는 화면 Refresh이므로 새 게임 버튼 자체는 연결/게임 진입을 요청하지 않음.
- 결과적으로 요청한 “청강코드 창 열기 → 새 게임 → 접속”과 실제 동작의 실행 지점이 다름.
- 수정안: 아이콘은 창만 열기. 새 게임은 초기화 후 기존 연결/로딩/게임 시작 경로를 호출하도록 연결함.
- 기존 첫 플레이 시작/건너뛰기와 튜토리얼 재실행 정책은 별도 유지 필요함. 게임 진입 지점을 추가할 때 기존 정책을 우회하지 않도록 함.

관련: [앱 바인딩](../../Assets/Scripts/Presentation/Desktop/DesktopAppBinding.cs), [청강코드 창](../../Assets/Scripts/Presentation/Desktop/ChungkangCodeWindow.cs), [메인 컨트롤러](../../Assets/Scripts/Presentation/MainMenuController.cs).

## 3. 문서함 안내 단계부터 작업표시줄 재배치

**원인 경로: 튜토리얼 강조 코드가 레이아웃에 참여하는 아이콘과 상위 그룹의 sibling 순서를 변경함.**

- `TutorialController`가 문서함 안내 단계에서 `LibraryLauncher`를 강조 대상으로 전달함.
- `TutorialOverlay.Show → Raise`는 대상부터 원본 Canvas 직전까지 모든 조상을 `RememberAndRaise`에 전달함.
- `RememberAndRaise`는 `SetAsLastSibling()`을 호출함. 강조 활성 중에도 반복됨.
- 따라서 문서함 아이콘만 표시상 강조되는 것이 아니라 `FixedApps` 등 상위 그룹까지 계층 순서가 바뀜.
- 실제 TutorialScene의 `Taskbar/DownloadedItems`에는 활성 HorizontalLayoutGroup이 있으며, 직접 자식은 FixedApps와 ManagedWindows임.
- FixedApps가 마지막 자식으로 이동하면 부모 레이아웃이 두 영역의 배치 순서를 다시 계산함.
- 초기에는 정상이고 문서함 단계 진입 후 뒤틀리는 사용자 관찰과 일치함. 초기 레이아웃 설정 자체만의 문제로 볼 수 없음.
- 기존 순서 복원은 Overlay 종료 시 수행되어 단계 진행 중 변형을 막지 못함.
- 수정안: 강조를 위한 sibling 변경 제거. 원본 RectTransform의 좌표를 읽어 별도 강조 프레임만 따라가게 함.
- 필요한 창 전면 표시는 기존 창 관리자에 맡기고, 작업표시줄/레이아웃 조상 순서는 변경하지 않음.
- 실제 Play 재현은 미수행함. 코드와 저장 계층으로 재배치 경로를 확인한 상태임.

관련: [튜토리얼 컨트롤러](../../Assets/Scripts/Tutorial/TutorialController.cs), [강조 오버레이](../../Assets/Scripts/Tutorial/TutorialOverlay.cs).

## 수정 후 확인 항목

- 메인 화면: 튜토리얼 아이콘 표시 및 재실행 진입.
- 청강코드 아이콘: 창만 열림. 새 게임 버튼: 연결/로딩 후 적절한 첫 플레이 또는 일반 게임 진입.
- 문서함 단계 전후 및 질문·팀·일정·메모장 강조 전후: 아이콘/그룹 sibling 순서와 위치 유지.
- 다운로드 문서 두 개 및 관리 창의 작업표시줄 항목이 존재하는 상태에서도 확인 필요함.

## 작업표시줄 수정 적용 — 2026-10-21

- `TutorialOverlay`의 Raise/RememberAndRaise, 순서 기록·복원, Show/LateUpdate의 계층 승격 호출 제거함.
- 제거 전 코드·씬·프리팹 참조 검색함. 외부 메서드 참조 없음 확인함.
- 강조 프레임은 기존 Follow의 대상 월드 좌표 추적만 사용함. 강조 대상과 상위 레이아웃의 sibling 순서를 변경하지 않음.
- Raycast 입력 통과 및 단계 진행 조건 유지함. 씬·프리팹 재배치 없음.
- Play·테스트·명시적 빌드 명령·커밋 미수행함. 이미 순서가 바뀐 Play 실행은 종료 후 튜토리얼을 다시 시작해야 저장된 원래 배치로 시작함.
