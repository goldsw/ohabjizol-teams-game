# 위험과 개선

## 실제 문제와 확장 위험

- 실제 버그: 확정 건 없음. 중복 완료·닫기 취소·버튼 비활성화 오류 근거 없음.
- 확장 위험 1: Controller.Index는 Application 외 모든 종류를 동일 슬롯으로 취급하고 View 기존 이벤트도 Application 외에는 Portfolio로 전달함. 현재 두 버튼만 시작하므로 현행 결함 아님. Schedule/InterviewRecord 다운로드 추가 시 명시적 매핑 필요함(Controller 15, 20행, View 46–47, 94–95행, Kind 3–8행).
- 확장 위험 2: 정상 Awake 후 Configure로 버튼 교체 시 이전 리스너 잔존·새 버튼 미연결 가능함. 참조 누락으로 Awake 반환 후 Configure만 해도 연결 복구되지 않음. 실제 런타임 재설정 사용은 확인되지 않음(View 71–90행).
- Authoring의 Configure·CloseImmediate 호출은 확인됨. 작성 도구 문맥이며 해당 호출만으로 런타임 초기화 버그를 확정하지 않음(Authoring 92–101행).
- 수명 확장 시 주의: Controller가 View에 소유되어 View 파괴 시 취소됨. 화면을 떠나도 계속 다운로드해야 한다는 요구가 생기면 현재 취소 정책·소유 수명 변경 필요함(View 21, 84–87행).

## 최소 책임 분리 제안

- 현재 분리 유지 권장함. UI는 View, 작업 상태는 Controller, workspace 연결은 Presenter, Tick·화면 수명은 Runtime이 담당함.
- 문서 종류 확장 시 종류별 상태·이벤트 매핑부터 개선 가능함. 화면 파괴 후에도 지속해야 할 때 Controller 소유권 이동 검토함.
- 기존 이벤트는 호환 목적 확인 후 정리 여부 결정 가능함. 단순 Image/Sprite 스킨 작업과 다운로드 구조 변경을 묶을 필요 없음.
