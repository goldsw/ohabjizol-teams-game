# 검증과 초기 상태 책임
## 현행 흐름
- 문서는 다운로드 후 작업표시줄에 생성함. 면접 초기 상태에 문서 창이 미리 배치된 것으로 가정하지 않음.
- WindowInitialStateSetup/Validation은 기존 창 프레임과 현재 직렬화 필드의 초기 상태를 담당함.
- InterviewRefreshRuntimeValidation은 실행 검증과 진행 저장 키의 백업·복구 담당함.
- ResponsibilityRefactorValidation은 이전 기록 변환·완료 중복·회차 격리·저널 복구 담당함.

## 이전 도구 호환
- 현재 InterviewScreen에는 initialDocuments 필드가 없음. 필수로 요구하는 이전 Editor 도구는 새 다운로드 흐름과 불일치함.
- 초기 상태 도구는 필드가 존재하는 이전 구조에는 해당 검증을 적용하고, 현행 구조에는 discordVisible과 창 프레임 검증을 적용함.
- 누락된 초기 문서 필드를 런타임에 다시 추가하여 다운로드 전 문서를 생성하지 않음.
- 기존 창 프레임 Build 1회·초기 표시·열기/닫기·부모 숨김 계약은 계속 검증함.

## 적용 범위
- D: Assets/Editor/WindowInitialStateSetup.cs, WindowInitialStateValidation.cs의 이전 문서 상태 요구를 호환 처리함.
- 기존 코드 GUID와 씬/프리팹 데이터를 편집하지 않음. 에디터 검증 방식만 현행 직렬화 구조에 맞춤.
- 런타임 저장 백업 수정은 B, 면접 수명 검증은 A, 통합 검증과 결과 문서는 부모 담당함.


## 프리팹 저장값 검증
- 현재 InterviewScreen은 씬이 참조하는 prefab 내부 컴포넌트임. scene YAML에 inline m_Script 블록이 없다고 참조 누락으로 판단하지 않음.
- source prefab의 GUID/localID로 실제 컴포넌트 블록을 찾고 script GUID를 확인함. 정확한 대상·propertyPath의 scene override가 있으면 그 저장값을 사용함.
- loaded bool과 저장된 effective bool을 비교함. 블록 누락/중복·override 중복·잘못된 bool·미지원 상속 구조는 명시적 실패함.
- 초기 상태 Setup은 이미 저장된 prefab 값에는 변경 없이 통과함. 새 필드가 source prefab에 저장되지 않은 경우 authoring 저장 필요를 보고하며 임의로 씬/프리팹을 덮어쓰지 않음.
- 실제 Pipeline 재검증: 일반 prefab의 source GUID/localID·씬 override 대조 및 창 초기 상태 검증 PASS 확인함. 검증 결과는 [현행 검증 기록](../아키텍처/04_검증.md)에 기록함.
