# 진행 저장 책임
## 저장소
- StageProgressStore: 영구 클리어 여부·최고 정확도 담당함. 기록은 스테이지 ID 기반 새 스키마로 저장함.
- CampaignRunStore: 한 회차의 ID·스테이지 완료·별 점수 담당함. 실패도 완료 기록으로 다음 스테이지에 진행함.
- StageCompletionService: 두 기록의 완료 작업·중복 방지·중단 복구 담당함.
- ResultSceneEntry: 확정된 결과 표시 담당함. 표시를 위해 결과 씬을 다시 열어도 진행을 기록하지 않음.

## 공유 API
- Complete(string runId, InterviewResult result): 현재 회차와 결과 스테이지 검증 후 완료 기록함.
- RecoverPending(): 보류된 완료 작업을 재시도함. 새 회차를 이전 기록으로 오염시키지 않음.
- PersistenceKeys: 서비스와 저장소가 소유한 모든 PlayerPrefs 키를 검증 도구에 제공함.

## 이전 데이터
- v1 배열 기록은 기존 스테이지 ID 순서에 따라 변환함. 길이가 다르다는 이유만으로 전체 기록을 초기화하지 않음.
- 같은 스테이지의 최고 점수·클리어 이력은 이전 기록에서 보존함. 새 스테이지는 기본값으로 생성함.
- 부분 배열·중복 ID·알 수 없는 ID·손상 형식의 처리 정책을 명시하고, 정상 레코드를 살릴 수 있으면 보존함.
- 변환 전 원본을 보존하고 새 스키마 기록 성공 후 정상 로드함. 명시적 Reset은 관련 이전/신규 키 모두 처리함.

## 완료·복구
- 완료 작업은 RunId·StageId로 식별함. 동일 결과 재시도는 중복 점수나 다음 스테이지 추가 진행을 만들지 않음.
- 저장 전에 완료 작업의 복구 정보를 남기고, 두 기록 성공 후 완료 확정함. 단순 순차 저장을 원자성으로 간주하지 않음.
- 다른 회차의 완료 요청이나 서로 다른 중복 결과를 조용히 덮어쓰지 않음.
- 완료 대기 복구는 회차 문맥을 읽기 전에 수행함. 저장 실패 시 보류 기록을 남김.

## 검증
- 기존 Editor 런타임 검증은 PersistenceKeys 전체를 백업·복구함. 신규 저장 키를 검증 후 남기지 않음.
- 이전 기록 변환·반복 완료·중간 실패 복구·새 회차 격리·결과 씬 재진입을 확인함.
- B가 저장/결과 진입/검증 백업을 수정함. StageContext/StageManager는 A 소유임.
