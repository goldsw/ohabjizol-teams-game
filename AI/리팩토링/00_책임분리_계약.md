## 작업 분배
- A: InterviewScreen, 새 면접 Runtime 클래스, InterviewRefreshRuntimeProbe. 질문 상태와 지원자 전환·문서·알림 표현 분리 담당함.
- B: StageProgressStore, CampaignRunStore, StageCompletionService, 필요한 StageProgress/CampaignRunProgress, ResultSceneEntry, InterviewRefreshRuntimeValidation. 저장과 검증 백업 담당함.
- C: DesktopView, 앱 연결 클래스, 필요 desktop 창 클래스. Inspector 앱 목록과 호환 이관 담당함.
- 부모: 계약 확인·통합·검증·실제 아키텍처 문서 갱신 담당함. 작업자 쓰기 범위를 겹치지 않게 유지함.

## 공통 API 계약
- B 제공: public static void StageCompletionService.Complete(string runId, InterviewResult result).
- B 제공: public static void StageCompletionService.RecoverPending().
- B 제공: public static System.Collections.Generic.IReadOnlyList<string> StageCompletionService.PersistenceKeys { get; }.
- Complete는 성공/이미 동일 결과 반영 시 정상 반환함. 오래된 RunId·서로 다른 중복 결과·저장 실패는 예외로 보고함. 기록 확정 전 씬 전환 금지함.
- A는 진입 전 RecoverPending 호출 후 회차·스테이지 문맥을 한 번 확정함. 완료 콜백은 Complete로 연결함.
- StageManager·StageContext는 Ohabjizol.Interview 영역임. 기존 Ohabjizol.Managers의 사운드용 타입과 구분함.

## 호환·검증
- 기존 MonoBehaviour 스크립트 GUID·직렬화 이름·공개 API·에디터 Bake 계약 보존함.
- GameObject/창의 표시 상태와 도메인 수명을 구분함. 이벤트 구독·해제 대칭과 재활성화 시 상태 표시 보장함.
- 사용자 기존 수정·미추적 파일 위에서 필요한 부분만 편집함. 이번 작업에 커밋은 포함하지 않음.
- Editor 프로세스 0개 확인됨. 이전 사용자 승인에 따라 Unity CLI 배치 컴파일·검증 가능함. 이 승인은 작업지침의 일반 batchmode 제한보다 우선함.
- 검증 로그는 파일에 남기고 결과·핵심 오류만 보고함. 기존 70% 클리어·실패도 다음 진행·4스테이지 엔딩을 검증함.


## 구현 전 확정한 세부 정책
- RecoverPending 실패는 진입 실패로 보고하고 새 세션을 만들지 않음.
- 질문 사용 수는 응답 중 예약을 포함하며 취소 시 복구함. 화면 재활성화는 지원자 식별·포트폴리오 표시 상태를 변경하지 않음.
- 완료 중복 확인은 다음 스테이지 검증 전에 수행함. 동일 회차·스테이지·결과의 재시도는 정상 성공임.
- v1 인덱스는 EntranceGameJam, GameProgrammingIntro, SecondYear, ThirdYear 순서에 고정 매핑함.
- 정상 부분 레코드는 보존함. 동일 ID는 최고 점수·클리어 OR로 병합하고 미지원 ID는 활성 도메인에 적용하지 않음. 지원하지 않는 미래 스키마를 정상 기록으로 간주하지 않음.
- 회차 기록 변환은 기존 RunId·완료·점수를 유지함. 보류 기록은 다른 회차에 적용하지 않음.
- B가 필요하면 Rules/ResultCarry.cs도 수정할 수 있음. MainMenuController의 통합 수정은 부모만 담당함.
- Inspector 앱 목록이 명시적으로 있으면 기존 기본 앱을 재추가하지 않음. initialDocuments 등 reflection 이름은 보존함.
- [검증과 초기 상태 호환](04_검증과초기상태.md): 현행 다운로드 흐름을 기준으로 이전 Editor 도구를 호환 처리함.
