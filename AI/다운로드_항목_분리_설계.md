# 다운로드 항목 분리 계약

## 확정 범위

- 기존 항목 입력 → Fill=100% → SkinDownloadIcon=Check → Panel.DownloadCompleted → 기존 문서 열기 순서 보장함.
- 변경 전 실측: Play 정지, DownloadPanel의 DownloadApplication/DownloadPortfolio 버튼·각 ProgressFill 정상 연결, 시간 0.2~1초, 두 아이콘 nativeSprite=download임.
- 변경 전 refs 기록: Logs/DownloadItemRefactor/Before/panel-bindings.json, SceneSaveAsCopy 백업 완료됨. 이전 전 SceneDirty=true였음.

## 코어 API

- DownloadItemView: 기존 Button마다 1개, 단일 DocumentDownloadController 소유함.
- 직렬화명: _kind/_button/_fill/_statusIcon/_downloadSprite/_checkSprite/_minimumDownloadSeconds/_maximumDownloadSeconds로 고정함.
- 공개 계약: `DocumentKind Kind { get; }`, `event Action<DocumentDownloadRequest> Completed`, `BindContext(string key)`, `CancelPending()`, `bool IsCurrent(DocumentDownloadRequest request)`, `TickDownloads(float deltaTime)`임.
- Item 추가 공개 계약: `bool HasAuthoredUi { get; }`, `Button Button { get; }`임. HasAuthoredUi는 kind·버튼·Fill·상태 Icon·두 Sprite 필수 참조 검증에 사용함. Panel 런타임 검증과 EditorSkin은 이 공개 계약을 사용하며 private legacy 필드에 의존하지 않음.
- Item Editor 계약: `#if UNITY_EDITOR` 안에 `public void ConfigureEditor(DocumentKind kind, Button button, Image fill, Image statusIcon, Sprite downloadSprite, Sprite checkSprite, float minSeconds, float maxSeconds)` 제공함. 순수 참조·설정값 할당만 수행하며 Play 중에는 변경 전 거부함. UI 생성·리스너 연결·진행 상태 변경하지 않음. B가 직렬화 이관에 사용함.
- Controller는 기존 파일·클래스와 Request 타입 유지함. 생성자 `(DocumentKind kind)`, `Begin(float duration)`, `Tick(float deltaTime)`, `BindContext(string key)`, `CancelPending()`, `bool IsCurrent(DocumentDownloadRequest request)`, `float Progress { get; }`, `bool IsCompleted { get; }`, `event Action<DocumentDownloadRequest> Completed` 제공함.
- Luna 확인: Controller 직접 생성은 Panel 한 곳뿐임. Panel 생성 책임을 Item으로 옮기고 Job[2]/Index의 else=Portfolio 제거함. Application/Portfolio만 명시 허용함.
- 빈 key·진행 중·완료 후 Begin 거부함. duration은 0.2~1초, 음수 delta는 0으로 처리함.

## Panel API·수명주기

- Panel은 _items 배열·슬라이드/close·context/cancel/Tick 분배·완료 중계 담당함. 개별 버튼 입력·진행 계산·Fill/Icon 조작은 Item 담당함.
- Panel 추가 공개 계약: `public IReadOnlyList<DownloadItemView> Items { get; }`임. 미설정 시 빈 목록 반환함. 조회 전용으로 제공하고 EditorSkin이 항목의 공개 Button/HasAuthoredUi와 함께 사용함.
- 기존 BindContext/CancelPending/IsCurrent/TickDownloads/DownloadCompleted 서명 유지함. IsCurrent는 request.Kind와 일치하는 Item에 위임, null/미지원 kind는 false임. 중복 kind 구성 거부함.
- Item은 Controller 완료 수신 시 Fill=1·Check 적용 후 Completed 호출함. 이벤트 반환 뒤 이전 UI 쓰기 금지함.
- 동일 key BindContext는 유지, 변경 시 generation 취소·상태/Fill 초기화·downloadSprite 복원함. null 바인딩은 초기화함. CancelPending은 generation 증가·미완료 초기화·완료 Check 유지함.
- Panel은 key 변경/CancelPending/파괴 때 revision 증가함. Tick 시작 revision 저장, 각 Item.TickDownloads 반환 뒤 변경되면 순회 중단함. 콜백의 지원자 교체 후 새 항목에 이전 delta 적용 방지함.
- 초기화는 멱등함. Panel이 비활성 자식도 명시 초기화·완료 구독한 뒤 bind/tick함. Item Awake와 외부 API는 동일 초기화 사용함.
- isActiveAndEnabled 검사는 Item 입력 시작에만 적용함. Panel 닫기/단독 OnDisable·Item 비활성 후 외부 Tick 계속함. OnDisable에서 작업 취소·구독 해제하지 않음.
- Screen 종료는 Presenter.Unsubscribe→CancelPending, 지원자 교체는 Clear→BindContext(null)→새 key 유지함.
- Item OnDestroy는 취소·Controller/버튼 리스너 해제함. Panel OnDestroy는 취소·Item/close 구독 해제함. 파괴 Item은 분배에서 제외함.
- Luna 확인: legacy ApplicationRequested/PortfolioRequested 외부 구독 없음. 두 이벤트와 중계 제거 가능함. 완료 계약은 DownloadCompleted로 고정함. Presenter/Runtime 변경 불필요함.

## Editor 이전·Bake

- Panel의 기존 버튼/fill/minmax 직렬화 필드는 이름·타입 그대로 숨김 보존함. Editor 이전 원본이며 이번 작업에서 삭제하지 않음.
- Panel Configure/ConfigureProgressEditor 기존 서명 유지함. 실제 caller는 각각 InterviewScreen.Authoring.cs:100, Assets/Editor/InterviewRefresh/DownloadFeedbackBake.cs:25임. 플레이 중 참조 변경은 변경 전 거부함. Panel partial + 같은 런타임 assembly의 DownloadPanelView.Authoring.cs로 authoring 분리 가능함.
- UnityEditor 사용은 UNITY_EDITOR로 제한함. 런타임 assembly에서 Assets/Editor 클래스 직접 참조 금지함.
- Editor 사전 확인: 두 기존 Button/Fill/Icon/시간과 Check/download Sprite 모두 확보함. Undo 기록 후 기존 Button에만 Item 추가, 직렬화 계약대로 복사·Panel._items 연결함.
- native Sprite는 Assets/Art/Discord/Source/Aseprite/디코 통화방 UI의 Check.aseprite/download.aseprite에서 Editor가 서브에셋 이름·13×13 확인 후 할당함. 런타임 AssetDatabase 조회·UI 생성 금지함.
- 유효한 _items는 이전 완료로 취급함. 재실행 시 중복 생성·값 덮어쓰기 금지함. 부분 구성/누락은 저장 전 오류 처리함.
- DownloadFeedbackBake는 PreflightItemsEditor → EnsureItemsEditor 경로로 연결함. ConfigureProgressEditor는 기존 legacy Fill refs를 보존하며 이미 구성된 Item의 다른 Fill로 교체는 거부함. Item 생성 전 호출한 refs는 이후 이전 시 복사함. 부분 연결 상태를 저장하지 않음.
- 신규 Assets/Editor/InterviewRefresh/DownloadPanelItemBake.cs는 명시적 sceneApply 메뉴 담당함. 기존 refs 사전 확인·Undo·Item.ConfigureEditor 이관·Panel 배열 연결 후 dirty 상태로 둠. 부모가 대상 씬만 저장함. Play 중 실행 거부, 전체 씬 저장 금지함.
- BakeAuthoredUi/DownloadFeedbackBake는 Item의 DownloadSprite·CheckSprite를 모두 연결함. 스킨 적용기는 이전된 Item의 Button을 경유하며 두 상태 Sprite 참조를 보존함.
- 스킨 적용기 :147의 download 지정과 :213~218/:258~260의 Source.sprite 덮어쓰기는 Editor 초기 외형에만 적용함. 두 상태 Sprite 직렬화 뒤 Item이 실행 중 아이콘을 결정하며, 스킨 적용이 Check 참조를 download로 덮지 않게 함.
- 신규 필드 컴파일 완료 후 legacy refs와 백업 대조→명시적 Apply→해당 씬 targetSave 수행함. Dirty 선행 guard를 피하려는 전체 저장 금지함. 기존 편집 유지함.
- Discord_total.png 배경 복원 상태 최우선 보존함. 빈 DISCORD.aseprite·레이아웃·질문·캐릭터·문서 태스크바 변경 금지함.

- 코어 A: Assets/Scripts/Interview/Runtime/DocumentDownloadController.cs, UI/DownloadItemView.cs 및 신규 meta만 담당함.
