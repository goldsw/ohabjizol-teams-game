# 다운로드 항목 분리 적용

## 상태와 목표

- 구현·현재 InterviewScene 적용·저장 완료함. [구조 계약](다운로드_항목_분리_설계.md)을 기준으로 분리함.
- 지원서·포트폴리오 각각 입력 → 진행 Fill → Check 아이콘 → 패널에 완료 반환을 담당함.
- 기존 다운로드 시간 0.2~1초, 진행 중·완료 후 중복 시작 방지 정책 유지함.

## 책임

- `DownloadItemView`: 자기 Button 입력, 진행률 표시, SkinDownloadIcon의 download/Check 교체, 완료 이벤트 담당함.
- `DocumentDownloadController`: 한 항목의 요청·시간·진행률·완료·지원자 키와 generation 담당함. UI 참조 없음.
- `DownloadPanelView`: 슬라이드·닫기, 항목 목록 배선, 컨텍스트·Tick·취소 분배, 완료 이벤트 중계 담당함.
- `InterviewDocumentPresenter`: 유효한 완료 요청을 DocumentWorkspace로 전달함. 기존 문서 보관·자동 열기 경로 유지함.
- `InterviewRuntime`: 화면 활성 중 unscaledDeltaTime을 전달함. 패널을 닫아도 Tick은 계속됨.

## 완료 순서

1. 버튼 클릭 시 해당 항목의 Controller만 시작함.
2. 해당 항목이 자신의 ProgressFill을 갱신함.
3. 완료 시 Fill을 100%로 설정하고 동일한 SkinDownloadIcon Image에 Check Sprite를 지정함.
4. 항목의 Completed(request)를 패널에 반환함.
5. 패널이 DownloadCompleted(request)를 중계함.
6. 기존 Presenter가 요청 유효성을 확인하고 문서를 보관·열기 처리함.

- 완료 콜백에서 지원자가 바뀌면 새 지원자의 아이콘·Fill에 이전 작업 결과를 덮어쓰지 않음.
- 한 항목 완료 중 컨텍스트가 바뀌면 패널은 그 프레임의 나머지 항목 Tick을 중단함.

## 수명과 초기화

- 패널 닫기·패널/항목 단독 비활성화는 진행 작업을 취소하지 않음. 외부 Tick이 유지되는 동안 진행함.
- 지원자 교체는 키·generation을 변경하고 Fill과 아이콘을 초기화함.
- 진행 중 취소는 Fill 0%·download 아이콘으로 되돌림. 완료 상태 취소는 완료 표시를 유지함.
- 화면 종료는 기존 Presenter의 취소·구독 해제 정책을 따름.
- 각 항목의 입력 리스너와 완료 구독은 멱등 초기화하고 파괴 시 정리함.

## Unity Inspector

- 기존 `DownloadApplication`, `DownloadPortfolio` Button에 DownloadItemView를 연결함.
- 각 항목에 Kind, Button, Fill, Status Icon, Download Sprite, Check Sprite, 최소·최대 시간을 저장함.
- 기존 ProgressFill과 SkinDownloadIcon을 재사용함. 버튼이나 패널의 위치를 재생성하지 않음.
- Check 원본: `Assets/Art/Discord/Source/Aseprite/디코 통화방 UI/Check.aseprite`의 하위 Sprite `Check`임.
- 다운로드 원본: 같은 폴더 `download.aseprite`의 하위 Sprite `download`임.
- 런타임에서는 저장된 Sprite 참조만 사용함. AssetDatabase 조회·PNG 변환·UI 자동 생성 없음.

## 이전과 보존

- 기존 패널의 버튼·Fill·시간 직렬화 필드를 이관 원본으로 보존함.
- 유효하게 구성된 항목은 재적용 시 중복 생성하거나 개별 설정을 덮어쓰지 않음.
- 기존 Configure·ConfigureProgressEditor 호출 및 새 UI Bake 경로를 지원함. Play 중 참조 재설정은 거부함.
- 기존 스킨 적용기는 실제 항목의 Button을 사용하며 download·Check 참조를 유지함.
- `Discord_total.png` 배경, 질문·캐릭터·문서 창·작업표시줄과 기존 사용자 배치를 유지함.
- 원본 상태: `Logs/DownloadItemRefactor/Before`의 씬 사본·참조 기록·관련 코드 사본으로 보관함.

## 적용 기록

- Unity 6000.3.15f1의 실행 중인 Editor에서 컴파일 완료함. 오류 0건·경고 0건임.
- `Ohabjizol → Interview → Apply Download Items`로 현재 열린 InterviewScene의 두 기존 버튼에 적용함. 메뉴 자체는 저장하지 않음.
- Application·Portfolio 각각 DownloadItemView 1개, HasAuthoredUi=true, 기존 ProgressFill·SkinDownloadIcon 재사용 확인함.
- 두 항목에 native download·Check 하위 Sprite 연결함. 최소 0.2초·최대 1초, 초기 아이콘 download·Fill 0% 확인함.
- Discord_total.png 배경 1개·Image 활성 상태 유지 확인함. 런타임이 별도 UI prefab으로 현재 씬 배선을 교체하는 경로는 지정 검색 범위에서 확인되지 않음.
- 현재 InterviewScene만 명시적으로 저장함. saved=true·dirty=false·playing=false 결과 기록함. 기존 편집 내용은 씬 사본으로 먼저 보관함.
- 근거: `Logs/DownloadItemRefactor/recompile.json`, `apply.json`, `bindings-summary.json`, `save.json`임.
- PlayMode 미실행으로 실제 클릭·완료 연출은 이번 작업에서 실측하지 않음.
- 사용자 요청 없는 PlayMode 실행·테스트 추가·커밋은 수행하지 않음.
- [이전 구조 분석](코드분석/DownloadPanelView.md)은 리팩토링 전 구조의 기록임.
