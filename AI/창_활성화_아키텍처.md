## 목표와 저장 위치
- 저장된 Inspector 설정이 최초 표시 결정.
- 기존 런타임 UI 생성 방식 위에 씬·host 프리팹의 초기 표시 설정 추가.
- 완성된 창 프리팹으로 전환하거나 씬 창을 직접 바인딩하는 변경은 별도 범위.
- MainMenuController: [SerializeField] DesktopInitialState initialWindows.
- InterviewScreen: [SerializeField] bool discordVisible = true.
- InterviewScreen: [SerializeField] DocumentInitialState initialDocuments.
- 두 State는 [Serializable] 클래스, 창별 bool 필드를 Inspector에 노출.
- 메뉴 기본값: codeOpen/settingsOpen/tutorialOpen 모두 false.
- 문서 기본값: applicationOpen=true, portfolioOpen/scheduleOpen/interviewRecordOpen=false.
- 설정은 Edit Mode에서 씬 또는 host 프리팹에 저장.
- 런타임 AddComponent 창에 필드만 추가하면 저장될 씬 객체가 없어 다음 실행에 유지되지 않음.
- 기존 두 씬에 기본값을 명시 저장. 누락 필드의 C# 초기값에만 의존하지 않음.

## 초기화와 공통 API
- WindowToolbar.Build: UI 구성만 수행. 마지막 강제 SetActive(false) 제거.
- WindowFactory.Create: 생성 GameObject를 먼저 비활성화하고 컴포넌트·내용 구성.
- Factory 기존 호출부의 기본 숨김 동작 유지.
- DesktopView.Build: DesktopInitialState를 인자로 받음.
- WindowToolbar.ApplyInitialState(bool): Bind·이벤트 구독 완료 후 최초 1회 적용.
- true: Open 경로로 갱신 및 Opened 이벤트 보장.
- false: 숨김 상태 유지. 초기 Closed 이벤트 발생하지 않음.
- 중복 초기 적용은 재개방하지 않도록 보호.
- 초기 codeOpen=true는 창 표시만 의미. 접속 코루틴은 아이콘 실행 시에만 시작.
- 초기화 이후 Open/Close/Toggle이 런타임 상태 담당.
- Awake/Start의 생성 절차 종료 시 초기 설정을 한 번 적용하고, Refresh/OnValidate에서 재적용하지 않음.
- IsOpen은 activeSelf 의미 유지. 부모 비활성에 따른 실제 표시 여부와 구분.
- 필요 시 실제 표시 조회는 activeInHierarchy 사용. 부모 숨김으로 개별 창의 열림 의도 변경하지 않음.
- 청강코드 창 닫기 시 접속 취소 동작 유지.

## Discord 루트와 소유권
- InterviewScreen host와 세션은 활성 유지.
- DiscordViewRoot에 통화 배경·영상·면접 조작 UI 배치.
- 문서 창 레이어·작업표시줄은 별도 형제 루트로 유지.
- SetDiscordVisible(bool)과 작업표시줄 표시 토글 제공.
- Discord 숨김은 세션 일시정지·종료 의미가 아님.
- 숨겨도 작업표시줄에서 재표시 가능.
- MainMenu는 직접 생성한 GeneratedDesktopRoot만 정리.
- 소유 루트 참조 사용. 다른 Canvas 자식 보존.
- 기존 자식을 일괄 삭제하지 않음.
- 런타임 재생성이 필요한 경우 새 창 구성·Bind·구독 후 초기 설정 한 번 적용.

## 단순 구현 분담
- 전원 gpt-6.1-sol / low, 제한된 문맥 사용.
- 구현 A: WindowToolbar.cs, WindowFactory.cs, 공통 초기 표시 적용 API.
- 구현 B: MainMenuController.cs, DesktopView.cs, DesktopInitialState.cs, MainMenuScene.unity.
- 구현 C: InterviewScreen.cs, DocumentInitialState.cs, InterviewScene.unity, Editor 설정 저장 도구.
- 신규 DTO는 담당 도메인 폴더에 두어 공통 UI가 게임 도메인에 의존하지 않도록 함.
- 각 신규 파일의 .meta도 해당 담당 소유.
- A의 API 확정 → B·C 병렬 → 통합·CLI 검증.
- 기존 프로젝트 A~D 작업지침의 에이전트 이름과 이번 구현 A~C는 별도 작업 범위임.
- C의 Editor 저장 도구는 B 소유 씬도 수정할 수 있으므로 병렬 작업 중 실행 금지.
- B·C 완료 후 통합 담당이 저장 도구를 실행하여 씬 설정 저장.
- 모든 에이전트는 지침 원본 직접 읽기. 재위임 메시지에도 원본·도구 절대 경로 전달.

## Unity CLI 최초 확인과 검증 계획
- CLI: C:\Users\eeseo\AppData\Local\Unity\bin\unity.exe.
- CLI 버전: 1.0.0-beta.11. 프로젝트·설치 Editor: 6000.3.15f1.
- --help, command --help, run --help 확인.
- status --json: 연결 0개, STATUS_NO_INSTANCES.
- 프로젝트 지정 command도 미연결 확인. Editor 실행 여부 자체는 확정하지 않음.
- Pipeline 연결 기반 실시간 명령은 연결 확보 필요.

```powershell
$u = 'C:\Users\eeseo\AppData\Local\Unity\bin\unity.exe'
$p = 'D:\UnityProjects\GitHub\Games\ohabjizol-teams-game'
& $u --no-banner --no-pager status --json

# 승인 후 Editor 메서드 구현 및 병렬 씬 작업 종료가 선행 조건.
& $u run $p --no-tail -- -executeMethod WindowInitialStateSetup.ApplyAndSave -quit
```
