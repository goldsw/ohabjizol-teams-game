# 메뉴·4스테이지 진행·엔딩

## 시작 연출
- 시작: 카메라 구도에서 모니터를 클릭할 수 있는 상태.
- 모니터 클릭 1회 → 모니터 줌인 → 컴퓨터 부팅 → 데스크톱 표시.
- 중복 클릭은 전환 시작 후 무시. 부팅 중 데스크톱 입력 잠금.
- 데스크톱 게임 시작 아이콘은 부팅 완료 후 확대된 크기 사용.
- 아이콘 크기·확대 애니메이션·카메라 구도·부팅 시간은 Inspector/애니메이션 자산에서 편집.
- 같은 실행에서 스테이지 종료 후 메인 복귀는 데스크톱 상태로 복귀. 시작 부팅을 매번 반복하지 않는 기본안.
- 최종 이미지 파일 없음 → 사용자 승인 주황 native UI 패널로 바탕화면 임시 제작함.
- 청강코드 더블클릭→창 등장→로딩 완료→줌→면접 씬 전환 유지.
- 설정·튜토리얼 아이콘 및 기존 설정 동작 유지. 고정 아이콘은 드래그하지 않음.

## 스테이지
- 입학 게임잼 → 겜프입 프로젝트 → 2학년 프로젝트 → 3학년 프로젝트.
- 사용자 확정: 성공/실패 모두 스테이지 완료로 기록하고 다음 단계 진행.
- 완료는 진행 조건, 정확도 70% 이상 clear는 별도 기록.
- 스테이지 1~3 결과 후 메인 화면에서 다음 스테이지 플레이.
- 스테이지 4 결과 후 엔딩 표시.

## 저장 분리
- 기존 StageProgress/StageProgressStore: 누적 clear 정보·최고 정확도 이력 유지.
- 신규 CampaignRun: runId·현재 단계·4개 완료 결과·별점·엔딩 상태 저장.
- 메인 다음 단계는 현재 run의 첫 미완료 stage로 결정. 역사상 미클리어 stage에서 멈추지 않음.
- 새 run의 점수에 과거 run 최고 점수를 섞지 않음.
- 각 stage 결과는 현재 run에서 1개만 확정. 결과 씬 재진입으로 중복 가산하지 않음.
- stage/result 식별자로 기록 소비를 멱등 처리. 이미 확정한 결과는 다시 더하지 않음.
- 기존 저장 키는 보존. 새로운 run 저장 키를 추가해 이력 초기화 없이 연결하는 기본안.
- 새 게임은 새 runId·4단계 점수 초기화. 과거 clear/최고점 이력은 유지.

## 엔딩 기본안
- 4스테이지 별 합계: 0~20, 0.5 단위.
- 좋음: 합계 15 이상.
- 보통: 합계 10 이상~15 미만.
- 나쁨: 합계 10 미만.
- 판정은 저장한 halfStarUnits 합계로 수행. 경계는 좋음>=30, 보통>=20, 나쁨<20.
- 임계값은 에디터 데이터에서 수정 가능하게 작성. 위 값은 설계 기본안.
- 예: 각 단계 80%→4별×4=16별→좋음.
- 예: 각 단계 60%→3별×4=12별→보통.
- 예: 각 단계 40%→2별×4=8별→나쁨.
- 실패도 진행하므로 세 엔딩 모두 도달 가능.
- EndingScene에 3종 UI/아트 참조 저장. 진행 데이터에 맞는 엔딩 선택 표시.
- 엔딩 내용·문구는 임시 데이터부터 구성하고 에디터에서 교체 가능하게 함.

## 결과 화면
- 기존 ResultBoard의 실제 직군 수치와 S/A/B/C/Fail 표시를 교체.
- 별 5개(full/half/empty), 현재 단계 완료 상태, 누적 별점 표시.
- 별 표시는 반별로 양자화되지만 clear는 기존 int 정확도 >=70 기준.
- '재도전' 안내 대신 다음 단계 또는 엔딩으로 진행하는 안내 사용.

## Play Mode 검증 결과
- Pipeline 컴파일·ApplyAndSave·정적 Validate 통과 상태 유지함.
- Play Mode Status PASS: 모니터 부팅·다운로드·더블클릭·최소화·질문 타이밍·지원자 정리 검증 통과함. 테스트 후 PlayMode=false 복귀 확인함.
- 최초 백그라운드 frame 1 정지 → Application.runInBackground 설정으로 해결함. 검증 helper의 자동 설정·원래 값 복원 완료함. 최종 결과는 [구현·검증 기록](./구현_검증.md) 참조함.
