# 요구사항과 확정 사항

## 상태
- 승인 설계에 따른 코드·native UI 자산 구현 및 scene/prefab 저장 완료. Inspector 편집 가능함.
- Pipeline 컴파일·ApplyAndSave·정적 Validate 현재 통과. Play Mode Status PASS: 모니터 부팅·다운로드·더블클릭·최소화·질문 타이밍·지원자 정리 검증 통과함. 테스트 후 PlayMode=false 복귀 확인함.
- UI scene/prefab 전환·질문·다운로드 문서·별점·엔딩 구현 반영함.

## 사용자 요구 1~9
1. 기획·아트·프로그래머별 포트폴리오·질문·응답 분기.
2. 직군 3종 × 좋음(파랑)/보통(노랑)/나쁨(빨강) 포트폴리오 표시 에셋 9종. 표시 색은 실제 수준과 독립적으로 랜덤 지정. 질의응답으로 실제 수준 유추.
3. 결과 등급을 별 5개로 교체. 1개=20%, 반 개=10%. 실제 능력치와 요구 능력치로 정확도 계산. 실제 수준 수치는 플레이어 UI에서 비공개.
4. 영상 지원자 주변 질문 버튼 5개. 질문 소진 전에도 즉시 합격/불합격 가능. 평상시 Idle. 질문 클릭 후 3초 동안 모션 순환·점 말풍선 반복, 이후 하단 지정 대사 출력.
5. 통화 하단 중앙=플레이어, 좌/우=동료 면접관. 새 지원자마다 우측 동료 말풍선 '새 면접자 서류입니다.' 및 우상단 채팅 버튼 ! 알림. 클릭 시 화면 밖 패널이 slide-in으로 통화 화면 덮기.
6. 패널 안 지원서·포트폴리오 다운로드 버튼 2개.
7. 미리 배치된 서류 아이콘 제거. 다운로드 완료 전 문서 항목을 노출하지 않음.
8. 다운로드 후 작업표시줄 PDF 항목 보관. 더블클릭하면 PDF 뷰어 열기. - 버튼은 최소화, X는 창 닫기. 툴바 드래그 유지.
9. 합격/불합격 결정 때 질문·말풍선·슬라이드·뷰어·작업표시줄 문서·알림 정리 후 다음 지원자 바인딩.

## 사용자 요구 10~14
- 배경·아이콘 개편. 최종 이미지 없음 → 사용자 승인 주황 native UI 패널로 임시 제작함.
- 시작 카메라에서 모니터 클릭 → 모니터 줌인 → 컴퓨터 부팅 → 데스크톱.
- 부팅 완료 후 게임 시작 아이콘을 확대된 크기로 표시.
- 4스테이지의 누적 별점으로 좋음/보통/나쁨 엔딩 분기.

## 확정한 진행 변경
- 사용자 선택: 실패해도 다음 스테이지 진행. 4개 결과로 엔딩 판정.
- completion(플레이 완료)과 clear(정확도 70% 이상)를 분리.
- 스테이지 1~3 결과 이후 메인으로 복귀해 다음 단계 실행. 4단계 결과 이후 엔딩으로 진행.
- 이전의 실패 시 동일 스테이지 재도전 기본안은 이번 진행 규칙으로 교체.

## 승인 설계·편집 가능한 기본값
- 질문 1개당 지원자별 1회. 질문 연출 중 다른 질문은 잠금, 합격/불합격은 항상 가능.
- 별점은 가까운 10%로 반올림. 정확히 중간이면 위로 반올림.
- 엔딩 기준: 최대 20별 중 좋음 15 이상, 보통 10 이상~15 미만, 나쁨 10 미만.
- 다운로드 항목은 현재 지원자 범위로 유지. 중복 클릭은 항목 추가하지 않음.
- X는 뷰어 닫기, 다운로드 항목 유지. -는 창 인스턴스·스크롤·위치 보존하여 최소화.
- AuthoredQuestionCatalog: 질문 15개·응답 45개, normalMinimum=3/goodMinimum=5. Inspector에서 질문·대사·임계값 교체 가능함.
