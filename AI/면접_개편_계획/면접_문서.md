# 면접·질문·다운로드 문서 생명주기

## 편집 가능한 구조
- Canvas 아래 통화 View·질문 View·하단 대사·슬라이드 패널·PDF 창 레이어·작업표시줄 scene/prefab 저장 완료. Inspector 편집 가능함.
- MonoBehaviour는 직렬화 참조로 연결. Awake/OnValidate에서 UI 구성·좌표를 재생성하지 않음.
- 반복 항목은 준비된 prefab 복제. 툴바·닫기·최소화·정보 콘텐츠는 prefab에서 편집.
- UI 초기 상태는 저장된 활성 체크를 원본으로 사용. 기존 초기 설정 DTO는 이관 시 한 번 반영.

## 통화 참가자
- 큰 영상: 현재 지원자.
- 하단 3명: 왼쪽 동료 면접관, 중앙 플레이어, 오른쪽 동료 면접관.
- 이 세 타일을 합격한 팀원 표시 용도로 재사용하지 않음.
- 평상시 지원자 Idle. 질문 중에만 Idle/Talk 모션 순환.

## 새 지원자
1. 이전 지원자의 작업을 무효화하고 새 applicantEpoch 발급.
2. 이름·직군·공개 데이터·초상·질문 5개 바인딩.
3. 질문 사용 상태·대사·PDF 항목·뷰어 초기화.
4. 우측 동료 말풍선 '새 면접자 서류입니다.' 및 우상단 ! 알림 표시.
5. 슬라이드 패널은 화면 밖 닫힌 위치로 초기화.

## 질문
- 버튼 클릭 즉시 해당 질문 사용 처리. 같은 질문은 다시 선택 불가.
- 3초 동안 지원자 모션 순환 및 '.'→'..'→'...'→'.' 말풍선 반복.
- 3초 뒤 하단 결과 대사 출력·말풍선 종료·Idle 복귀.
- 연출 중 다른 질문 잠금. 질문을 다 쓰지 않아도 합격/불합격 가능.
- 연출 중 판단하면 질문 타이머·모션·대사 예약 취소. 이전 답변을 다음 지원자에게 출력하지 않음.
- Coroutine 취소와 applicantEpoch 확인을 함께 사용. 추가 비동기 패키지 도입은 필요 시 별도 판단.

## 슬라이드 패널
- 우상단 말풍선 버튼 클릭: ! 확인 처리·우측 동료 알림 종료·슬라이드 인.
- 패널은 Unity UI로 통화창을 덮음. 두 버튼: 지원서 다운로드, 포트폴리오 다운로드.
- 슬라이드 시작/끝 위치·시간은 RectTransform·애니메이션/직렬화 설정에서 편집.
- 지원자 변경 시 슬라이드 중이라도 전환 취소 후 닫힌 위치로 복귀.

## 문서 상태
- 다운로드는 게임 내 문서 획득으로 구현.
- 키: (runId, stageId, applicantId, documentKind). 같은 키의 다운로드는 1개 항목만 생성.
- 다운로드 완료 때 작업표시줄 PDF 항목 추가. 시작 시 미리 놓인 문서 항목 없음.
- 더블클릭: 뷰어 표시 또는 최소화된 뷰어 복원.
- 툴바: 창 이동. 아이콘은 이동하지 않음.
- 최소화 -: 뷰어 인스턴스·내용·스크롤·위치 보존, 작업표시줄 항목 유지.
- 닫기 X: 뷰어 닫기, 다운로드 항목 유지. 다음 더블클릭으로 다시 열기 가능.
- 지원서: 공개 지원자 정보. 포트폴리오: 직군/표시 상태별 native UI 카드 prefab 9종·공개 설명, Noto 폰트 적용함.
- 창 상태는 Closed/Normal/Minimized로 구분. 최소화를 단순 삭제로 처리하지 않음.

## 합격/불합격
1. 판단 입력을 1회 확정·중복 입력 차단.
2. 현재 applicantEpoch 무효화 및 질문/대사/슬라이드 연출 취소.
3. 모든 PDF 뷰어·패널·다운로드 항목·알림 정리.
4. 기존 InterviewSession.Accept/Reject 수행.
5. 다음 지원자가 있으면 새 바인딩. 세션 종료면 결과 전달.
- UI 정리는 문서 자산 삭제가 아니라 현재 인스턴스/상태 정리.
- 선배치 문서 UI 제거 전 씬·prefab·코드 참조 전수 확인. 이미지·문서 데이터 자산 일괄 삭제하지 않음.

## 책임 경계
- InterviewScreen/presenter: 지원자 수명·질문·판단·세션 전환.
- DownloadPanelView: 패널 표시 및 다운로드 요청 이벤트.
- DocumentWorkspace: 다운로드 항목·PDF 뷰어·최소화·정리.
- DocumentWorkspace는 숨김 실제 능력치에 접근하지 않고 공개 문서 모델만 받음.

## Play Mode 검증 결과
- Pipeline 컴파일·ApplyAndSave·정적 Validate 통과 상태 유지함.
- Play Mode Status PASS: 모니터 부팅·다운로드·더블클릭·최소화·질문 타이밍·지원자 정리 검증 통과함. 테스트 후 PlayMode=false 복귀 확인함.
- 최초 백그라운드 frame 1 정지 → Application.runInBackground 설정으로 해결함. 검증 helper의 자동 설정·원래 값 복원 완료함. 최종 결과는 [구현·검증 기록](./구현_검증.md) 참조함.
