# 면접 게임 개편 계획

- 신규 14개 요구와 에디터 UI 편집 전환을 통합한 설계.
- 사용자 확정: 실패도 다음 단계 진행, 4스테이지 결과로 엔딩 판정.
- 규모: 작업 에이전트 5명 + 팀장 1명.
- 상태: 코드·native UI 자산 구현 및 scene/prefab 저장 완료. Inspector 편집 가능함.
- 기본안: 반별 반올림, 엔딩 좋음>=15별/보통>=10별/나쁨<10별.

- 근거: AGENTS.md의 원인/설계 확정 후 승인받고 구현하는 규칙.

## Play Mode 검증 결과
- Pipeline 컴파일·ApplyAndSave·정적 Validate 통과 상태 유지함.
- Play Mode Status PASS: 모니터 부팅·다운로드·더블클릭·최소화·질문 타이밍·지원자 정리 검증 통과함. 테스트 후 PlayMode=false 복귀 확인함.
- 최초 백그라운드 frame 1 정지 → Application.runInBackground 설정으로 해결함. 검증 helper의 자동 설정·원래 값 복원 및 campaign/stage-progress key 보존·복원 코드 구현 완료함. 실제 mainLaunch·Loading·4stage 실패 포함 진행·EndingBad·newRun Main 전체 루프 PASS. PlayMode 종료 frame 0 및 원래 InterviewScene SceneSetup 복원 확인함. campaign/stage-progress PlayerPrefs 두 키의 HasKey·값이 SessionState snapshot과 동일함을 확인함(restored=true).

- 최종 static Validate: 질문 15개·응답 45개 포함 PASS. playing=false, scene=Assets/Scenes/InterviewScene.unity 확인함.
